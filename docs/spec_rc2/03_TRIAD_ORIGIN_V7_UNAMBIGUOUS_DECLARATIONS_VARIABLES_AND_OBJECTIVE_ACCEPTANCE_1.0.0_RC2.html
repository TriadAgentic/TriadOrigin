Normative declaration of intent

This document removes silent ambiguity. Every consequential constant, threshold, window, unit, rounding rule, equality boundary, timeout, sample rule, authority limit and failure behavior in this RC2 implementation package is either (1) exact and already ratified/externally required, (2) an exact RC2 proposal that must be signed before activation, (3) deterministically venue/formula derived, or (4) the exact sentinel NOT_RATIFIED, which always blocks the affected authority. There is no runtime TBD and no hidden default.

Specification precedence

  1. Independent safety stop and venue/account truth.
  2. Signed activation and risk manifests for exact scope.
  3. This declaration/parameter registry.
  4. Formula and wiring registries.
  5. Contract schemas and state machines.
  6. Implementation. Code that disagrees is defective.

At the same level, the higher semantic version wins only when compatibility and migration manifests explicitly allow it. Otherwise: conflict → SAFE_HOLD.

Modal language

MUST / SHALL is mandatory. MUST NOT / SHALL NOT is prohibited. MAY is permitted only where the choice cannot change semantic, safety or economic output. SHOULD, “normally,” “recent,” “timely,” “significant,” “near,” “about,” “reasonable” and similar words are non-normative unless followed by an exact registry ID.

Truth boundary

Exact proposals are not claims of fitness or profitability. They become active only after their PAR-* checklist task, linked tests, evidence and due gate pass. Changing one value creates a new parameter digest, detector/capsule trial where semantic, and invalidates dependent evidence.

Unambiguous interpretation rules

QuestionNormative answer
What units cross boundaries?Price is signed int64 ticks; quantity is signed int64 steps; external/domain time is UTC Unix microseconds; durations are integer monotonic nanoseconds or a declared integer unit. Exact decimal/rational conversion only.
How is equality treated?Use the explicit operator. All registry phrases “at most/at least” are inclusive. A “strictly less/greater” phrase excludes equality. No epsilon.
How are values rounded?Quantity floors toward zero. Maker BUY floors and SELL ceils. Emergency worst prices use the safety direction stated by F22. A value already on grid is unchanged. No banker/nearest rounding in semantic or money paths.
Which clock establishes causality?Knowledge time is when all required source facts and confirming events were available. Old event time cannot move knowledge time backward. Publish/emission time is operational only.
What happens when an input is missing?Use the row’s failure behavior. Structure/candidate input becomes named null/abstention; risk denies; money state ambiguity blocks entries/reconciles; contract violation quarantines. Never use zero, neutral, prior or legacy value.
How are ties resolved?knowledge_time,event_time,source_sequence,root_id,revision_id, ascending. Exact duplicate identity is idempotent no-op.
Can a target/threshold be changed after seeing outcomes?No. Any semantic value change creates a new version and preregistered trial. Previous holdout/economic evidence cannot certify it.
Can the UI/workbook mark readiness?No. Only schema-valid immutable evidence/status records and a machine-derived signed gate receipt are authoritative.
Can low activity be called a pass?No. A metric with fewer than its declared denominator/sample is INSUFFICIENT. Safety stops may terminate a window, but an early safety stop is never profitability evidence.
Does a target SLO override safety?No. SLO breach with valid state may withhold promotion; stale/gapped/unknown safety state triggers the stronger row-specific block. Safety dominates latency and economic objectives.
