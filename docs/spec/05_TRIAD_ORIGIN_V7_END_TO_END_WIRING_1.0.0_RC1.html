05.2Deterministic control, intelligence treatment, and money routes

Control route

E00 market.events.v2
  → E01 market.state.v2
  → ORIGIN structures/reactions/candidate
  → E07 deterministic decision
  → E08 risk + reservation + execution authorization
  → E09 command/order/fill/position/protection
  → E10 outcome

Treatment route

same immutable ORIGIN candidate
  → E03–E06 advisory (separate advisory ID/version/availability)
  → E07 treatment decision (separate arm/decision ID)
  → prospective mutually exclusive allocation into the same E08/E09 path

Dark comparator

same market.state.v2 offsets
  ├─ frozen legacy bridge → control candidate
  └─ ORIGIN             → treatment candidate
       → semantic comparator → divergence_record.v1

Comparator has no E07/E08/E09 write permission.

Before/after calendar comparisons are not the primary release design. The comparator receives identical input offsets and records missing, extra, retimed, reidentified, geometry, lifecycle, quality, and downstream-eligibility divergences.

05.5Delivery, ordering, idempotency, retention, and backpressure

Phase-0 file-ledger binding

  • One authoritative writer lock per logical topic/partition. Ledger append is length-framed, checksummed/hash-chained and fsyncs according to the money/evidence durability class.
  • Consumer checkpoint records input segment/offset, last domain event ID, highest producer epoch, projection checksum, output segment/offset and build/config/contract digests.
  • Process input in deterministic partition order. Append state/output and checkpoint transactionally where practical; otherwise use idempotent output IDs and recovery verification.
  • Acknowledgement means durable semantic handling, not mere receipt. A consumer never advances its checkpoint past an event whose required output was not durably written.
  • Corrupt/torn frames stop the affected partition, preserve bytes, and create a quarantine/incident record. Do not skip silently.

Optional future JetStream binding

  • Assume at-least-once delivery. Nats-Msg-Id or equivalent transports event identity, but domain deduplication remains mandatory.
  • Explicit durable consumers; ACK only after state/output durability; bounded redelivery; named DLQ after policy exhaustion.
  • Per-subject/partition ordering, not fabricated global ordering. Retention, maximum delivery, duplicate window and replica/durability class enter the signed binding manifest.
  • JetStream health, consumer lag, stream replicas/storage, account limits, reconnect behavior, and disaster restore require separate certification. ORIGIN activation does not wait for an unprovisioned bus.

Backpressure hierarchy

  1. Preserve cancels, protection, venue/account reconciliation and risk-reducing exits.
  2. Stop new authorizations and entries before queues threaten evidence durability or freshness.
  3. Drop/recompute only explicitly disposable projections; never raw/money facts.
  4. Shed optional analytics/intelligence before deterministic state.
  5. Page on sustained lag, disk/ledger threat, or unknown money state.

Stream manifest

For every required stream: canonical ID, route family, URL template, subscription name, parser/version, instruments, required/optional, event-time field, venue sequence law, expected activity model, freshness/coverage rule, connection pool, rate cost, failure scope and replay storage. Startup fails if a stream is assigned to the wrong route.

Connection lifecycle

  • Market connections have a finite 24-hour lifetime. Schedule overlapping handover before the boundary; deduplicate by stream/session and venue sequence.
  • Server ping cadence and pong deadline are honored exactly (current documented values: ping every 3 minutes, pong within 10 minutes).
  • Throttle incoming client control messages to the current documented 10 messages/second and cap at 1,024 streams/connection.
  • Private listen keys are renewed before their finite validity; renewal failure and listenKeyExpired invalidate private-feed health and trigger full order/position/protection reconciliation.
  • Transport ping/pong proves socket liveness only. Per-stream coverage, freshness, sequence, parser and watermark determine feed health.

Authoritative route and limit details: Binance route migration and connection rules.

05.7Local order book, user stream, and execution feedback

Local book sequence law

  1. Connect to routed diff-depth and buffer events.
  2. Fetch REST snapshot.
  3. Discard buffered events with final update ID u < lastUpdateId.
  4. First retained event must satisfy U ≤ lastUpdateId ≤ u.
  5. Every later event must satisfy pu == previous u.
  6. Quantities are absolute; zero deletes a price level; deleting an absent level is harmless.
  7. Any continuity failure marks the book invalid and forces reinitialization. No new entry while invalid.

Private/order truth

  • Persist raw private events before normalization with session/listen-key/receipt sequence.
  • Merge and reconcile regular order events, Algo order events, open orders, open Algo orders, fills, positions and account snapshots.
  • Conditional STOP/TAKE_PROFIT families use the current Algo Service; consume ALGO_UPDATE. Old order paths may return -4120.
  • For ambiguous HTTP/WS submission status, enter SUBMISSION_UNKNOWN; search private stream and query by client order identity before retry.
  • Refresh and version exchangeInfo at startup and controlled intervals; status, tick, step, min notional, order types, trigger protection and other filters gate command compilation.

Order-book source: Binance local book procedure. Execution/algo sources are listed in Document 00.

05.8Startup, readiness, and authority-acquisition sequence

  1. Control plane: load signed contract/config/activation/transport/rollback manifests; verify artifact hashes, secrets allowlist and service identity.
  2. E09 safety plane: VGP authenticates; verify account/environment/position mode; start private stream; reconcile balances, regular/algo orders, fills, positions and protection. New entries remain disabled.
  3. E00: establish separate /public, /market and /private pools; verify subscriptions/coverage; start raw ledger.
  4. E01: bootstrap books/bars/metadata; reach READY watermarks; emit canonical checksums.
  5. ORIGIN: load checkpoint, replay to current E01 offset, prove state/output checksum, warm every enabled capsule and publish READY_NO_AUTHORITY.
  6. E07/E08: load policy/risk manifests, exposure snapshots and reservation ledger; prove default deny and exit availability.
  7. E10/evidence: verify strict fill/outcome/quarantine consumers and observability.
  8. Authority: governance issues exact producer lease only after all gate receipts match. Consumers test acceptance of current token and rejection of stale token.
  9. Canary: enable exact capsule/symbol/side/account scope; record promotion event. Code deployment alone never activates authority.

Readiness is semantic

PID, port, GUI, MCP initialize, or account count alone is insufficient. Readiness proves manifest equality, source freshness/coverage, state warm-up, checkpoint parity, writable owned ledgers, lease state, downstream acceptance, and expected side-effect capability (zero for dark).

05.9Graceful shutdown, restart, and failover

Planned ORIGIN shutdown

  1. Revoke or stop renewing candidate-authority lease.
  2. Stop consuming new candidate-eligible inputs; finish the current deterministic input transaction.
  3. Flush owned output journal and checkpoint; record state/output hashes and last offsets.
  4. Publish terminal lifecycle receipt and stop. ORIGIN owns no positions or orders to drain.

Money-plane shutdown

E09 cannot simply terminate while exposure exists. Disable new entries, maintain/repair protection, cancel stale entry orders, reconcile unknown submits/fills/positions, flatten or transfer explicit campaign ownership under policy, release reservations only after proof, then stop.

Failover

A replacement process loads the exact manifest/checkpoint, replays to the current offset, proves parity, and requests a strictly newer lease. Consumers fence the old epoch. There is never “latest timestamp wins.”

Trace propagation

Propagate W3C-style trace context or approved equivalent in envelopes and messaging spans. Create spans for consume, validate, state transition, publish, E07 decision, E08 reservation, E09 dispatch, venue ACK/fill and reconciliation. Trace IDs correlate work but never enter domain identity or signed economic semantics.

Cardinality

Metrics labels are bounded: service, contract major, topic, capsule, symbol capability group, state/reason enum, arm and environment. Event/order/candidate IDs belong in logs/traces, not metric labels. Logs are structured, secret-scrubbed, immutable where safety-material, and include event/producer/manifest IDs.

Immediate paging

Two active writers, stale epoch accepted, shadow reaching money, ledger append/fsync failure, authoritative digest mismatch, replay divergence, unknown/unprotected position, emergency exit/failure, protection reject/deadline, canary harm limit, rollback failure, raw credential outside VGP, or disk threat.

05.13Deployment bindings and rollout wiring

Environment progression is:

offline replay → integration replay → connected dark
→ treatment with zero authority → capped mutually exclusive treatment
→ controlled economic certification → scoped authority cutover
→ legacy observation → legacy retirement

Each deployment produces an immutable receipt with source commit, artifact/SBOM digest, contract/config/activation manifests, transport binding, service identity, startup checks, replay smoke hash and lease state. Blue/green process deployment occurs before authority transfer. Authority rollback is a manifest+lease operation, not merely a process restart.

Transport migration

If JetStream is adopted, mirror logical topics from the file-ledger source, compare event counts/IDs/order/checksums, dark-read with consumers, chaos-test redelivery/lag/restore, then change one binding at a time. Preserve the raw ledger until the new transport proves equal or stronger replay and disaster recovery.

05.14Read-only evidence and MCP wiring

MCP reads projections and ledger evidence through scoped read-only credentials. It reports four separate states: source implementation, deployment, runtime availability, and evidence completeness. A source flag or tool registration is never presented as a live producer.

Required ORIGIN read faces

  • attestation, activation and lease scope;
  • input offsets/watermarks/coverage/quality;
  • structure and lifecycle lineage with all clocks;
  • candidate funnel and named zero reasons;
  • control/treatment divergence;
  • fill.v3 completeness and fill→position→outcome reconciliation;
  • protection/emergency events;
  • replay receipts and test/promotion evidence.

Dark families remain disabled until configured and authenticated. Dependency absence is an honest unavailable, not an empty success. No MCP response contains bearer tokens, venue secrets, private payloads beyond approved fields, or operator control verbs.
