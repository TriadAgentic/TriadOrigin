04.1State-machine law

  • Each machine has one authoritative owner and an append-only event journal. Other services project the journal but never edit its state.
  • Every transition includes prior state sequence/transition ID and uses compare-and-append semantics. Concurrent conflicting transitions cannot both commit.
  • Terminal states are absorbing. Corrections are new events in a defined correction machine, never deletion or in-place mutation.
  • Unknown states, events, enum values, missing guards, stale epochs, and sequence gaps reject with a named reason.
  • A service crash after append but before acknowledgement is resolved by idempotent replay of the same transition identity.
  • Operational quality can block a semantic transition without changing already-confirmed semantic history.

Every table below is normative at the semantic level. Implementation may split a state into substates only if external behavior and transition evidence remain equivalent and the contract version does not change.

04.2Same-input transition precedence

When one accepted input could satisfy several transitions, evaluate in this strict order:

  1. contract/authenticity/producer-epoch rejection;
  2. data-quality invalidation or sequence gap;
  3. hard semantic invalidation/break;
  4. expiry;
  5. terminal fill/flat/reconciliation fact;
  6. cancel/reject fact;
  7. touch/trigger/confirmation;
  8. ordinary progression;
  9. heartbeat/no-op.

A higher-precedence transition consumes the input for that machine unless its definition explicitly allows an additional orthogonal event. Example: if an FVG is invalidated and touched by the same accepted observation, baseline v1 records invalidation only; it cannot publish a candidate.

Hard guards

  • after absolute exposure ≤ before absolute exposure;
  • quantity ≤ venue-reconciled current exposure;
  • no command can change flat to non-flat or cross through zero;

  • every emergency fill excluded from normal maker KPI and reported by cause/slippage/tail.

04.18Cross-machine invariants

  1. No E07 ALLOWED state without a currently valid, non-withdrawn candidate.
  2. No E08 reservation without an E07 decision, and no E09 authorization without a held reservation except a separately governed verified-exposure emergency exit.
  3. No new/increasing E09 command if partition quality, exposure, producer epoch, instrument metadata, or protection capacity is invalid.
  4. No strict fill without venue evidence; no position transition without a strict fill or authoritative account event; no outcome without position/fill reconciliation.
  5. An order may be terminal while its campaign remains open; a candidate may expire after an order exists without canceling it implicitly. Owners communicate through explicit events.
  6. Entry kill switches never disable cancel, protection, reconciliation, or risk-reducing exits.
  7. Risk reservation remains committed while any position/order ambiguity exists.
  8. Shadow/treatment without authority cannot create risk request, execution authorization, command, order or fill.
  9. Rollback revokes entry producer authority before a different producer can acquire the scope.
  10. Every state projection can be rebuilt from the append-only journal and matches the authoritative checksum.
