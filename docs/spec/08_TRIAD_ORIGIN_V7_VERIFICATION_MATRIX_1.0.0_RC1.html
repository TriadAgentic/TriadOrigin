08.1Falsification-first verification doctrine

  • A test is designed to disprove a requirement, not demonstrate a happy-path demo.
  • Every run pins input data/offsets, receipt-fidelity class, build, contracts, configs, parameters, instrument metadata, fee model, platform and producer epoch.
  • Target statuses start NOT_RUN. Prior audit PASS/FAIL overrides are historical evidence only and are deliberately not inherited as ORIGIN results.
  • PASS requires exact acceptance evidence. Missing sample/dependency is BLOCKED or INSUFFICIENT, never PASS.
  • P0 tests cannot be waived for affected money scope. A waiver for lower-criticality work needs owner, rationale, compensating control and expiry.
  • One critical invariant FAIL stops the affected gate regardless of aggregate pass percentage.

08.7Statistical and economic verification controls

  • Permanent trial-family ledger includes failures, abandoned ideas, renamed lanes, filters, thresholds, universes, exit variants and agent-generated experiments.
  • Chronological evaluation; nested selection inside training; purge overlapping outcome horizons; embargo the maximum dependency/outcome horizon.
  • Unit is deduplicated opportunity cluster/campaign, with dependence-preserving bootstrap or appropriate clustered inference.
  • Primary metric and sidedness frozen before results. Report uncertainty, not point estimate alone.
  • PBO evaluates selection over the complete configuration family. Deflated Sharpe uses actual trials, skew and kurtosis. Family-wise claims use a registered multiple-testing method such as Romano–Wolf.
  • Cost/fee/funding/slippage/emergency-exit and maker-fill uncertainty are explicit. Public L2 fill simulation is never labeled exact.
  • Parameter-neighborhood, side/symbol/regime, concentration, common-factor and worsening-cost/fill/latency sensitivity tests are mandatory.
  • Power/sample and sequential rules freeze before money evidence; undersized result is INSUFFICIENT.
Recommended values await ratification. One-sided 95% lower net-EV bound >0, DSR probability ≥95%, PBO ≤5% and Romano–Wolf adjusted significance ≤5% are project recommendations, not thresholds mandated by the cited papers.

08.8Release decision and defect policy

  1. Test runner emits immutable results and evidence hashes.
  2. Gate evaluator checks required test IDs, exact scope and absence of unresolved P0 failures.
  3. Independent reviewer validates evidence completeness and exceptions.
  4. Governance records PASS, FAIL or INSUFFICIENT for the exact capsule/symbol/side/account/build/manifest scope.
  5. PASS may issue a narrower activation manifest only; no implied global promotion.
  6. Any safety invariant failure revokes entry authority immediately and opens rollback/incident flow.
  7. Any semantic/economic change after PASS creates new build/parameter/trial identity and reruns affected gates.
