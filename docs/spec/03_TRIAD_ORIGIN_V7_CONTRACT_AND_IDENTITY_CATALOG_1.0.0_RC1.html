03.1Contract law

Published contract bytes are immutable. Breaking semantic or required-field changes create a new major version.
Every authoritative event validates before publication and again at the consuming authority boundary.
Unknown economically or safety-material data never defaults. It rejects or quarantines with raw evidence.
Only the named owner publishes authoritative facts; projections and readers do not originate truth.
Schema compatibility does not imply producer authority. A valid payload with a stale epoch is rejected.
Examples and generated clients are derivative artifacts. The signed schema/manifest and normative invariants prevail.

The target remains transport-neutral. A logical topic and contract retain the same semantics whether bound to the current append-only file ledger or a later certified JetStream deployment.

03.4Canonical encoding, numeric law, and ID construction

  • Canonical wire v1 is UTF-8 JSON with lexicographically sorted object keys, NFC-normalized strings, no duplicate keys, no NaN/Infinity, and no insignificant numeric alternatives.
  • Semantic price and quantity values are base-10 strings representing signed 64-bit tick/step integers. Time in microseconds may be JSON integer; monotonic/nanosecond values use decimal strings.
  • Enums are uppercase ASCII. Symbol strings never substitute for canonical_instrument_id.
  • Hash input uses length-prefixed canonical byte fields or canonical payload bytes with an explicit identity-schema version; raw concatenation is forbidden.
  • Derived event IDs are deterministic hashes. Venue/attempt facts may use time-sortable IDs, but must carry a stable economic idempotency key and venue identity.

Identity hierarchy

semantic_instance_id = hash(formula_version, parameter_digest, venue_model, timeframe)
structure_id = hash(identity_schema_version, instrument_id, venue_model,
                    structure_kind, semantic_instance_id, direction,
                    immutable_source_ids, original_geometry_digest)
reaction_id = hash(structure_id, reaction_formula, trigger_source_ids)
hypothesis_id = hash(reaction_id, capsule_version, parameter_digest)
candidate_id = hash(hypothesis_id, candidate_formula, publication_occurrence)

Mutable geometry revisions retain structure_id and increment state_seq.
Attempt/order/fill IDs never replace candidate/hypothesis identity.

03.5Market-state and feature profiles

market_event.v2 required payload

raw_event_id, venue, route family (PUBLIC|MARKET|PRIVATE), source stream, connection/session epoch, receive sequence, venue sequence/range where supplied, canonical and venue instrument IDs, event kind, raw payload hash/location, source event time, transaction time when supplied, local wall and monotonic receipt times, normalization time, instrument metadata revision, quality and parser version.

market_state.v2 required payload

State revision ID, partition key, state kind, canonical instrument, timeframe, source offset range, dependency event IDs, finalized/as-of event time, watermark completion, knowledge time, publication time, instrument revision, validity (SYNCING|READY|DEGRADED|GAPPED|STALE), gap/late/duplicate facts, book sequence state, bar finalization state, canonical values in ticks/steps, provenance hash and prior revision.

feature_snapshot.v2 required payload

Feature set/version, partition, exact as-of state revision, feature values with unit and validity, dependency ranges, formula/parameter digests, warm-up status, null/degraded reasons, source/knowledge/evaluation/publication clocks, and output hash. A scalar zero and an unavailable value are different wire states.

03.6Structure, transition, reaction, and candidate profiles

structure_atom.v2 required payload

structure_id, semantic instance, capsule-independent structure kind/subtype, instrument, venue model, timeframe, direction, origin/confirmation/availability/knowledge clocks and source IDs, original geometry in ticks, original geometry digest, reference level IDs, source offset range, dependency quality, formula/parameter/build/config/instrument digests, state CONFIRMED, and predecessor/causal structure refs.

structure_transition.v2 required payload

transition_id, structure_id, strictly increasing state_seq, previous transition ID, from/to state, reason enum, geometry revision, current geometry, event/receipt/knowledge/publication clocks, source/reference IDs, watermark, quality snapshot, and provenance hash. Terminal transition guards validate before append.

reaction_event.v1

Reaction ID, source structure/transition, location/departure/trigger/confirmation results, fresh flow-atom refs, first-touch ordinal, natural entry/invalidation/target ticks, geometric RR rational, cancellation causes, not-before and expiry times, and every dependency clock.

edge_candidate.v2

Candidate/hypothesis/opportunity-cluster IDs; capsule/version/parameter/trial; source structure/reaction; canonical instrument/direction/horizon; entry policy/reference; natural invalidation; targets; RR numerator/denominator; TTL/not-before/cancellation; cost-model and fill-model IDs; control/treatment/shadow arm; quality/prerequisites; complete digest/clock/provenance envelope.

Forbidden candidate fields. Final approval, account, notional, leverage, executable quantity, venue order IDs, raw credentials, invented expected return, or a direct E09 destination.

03.7Decision, risk, reservation, authorization, and command profiles

decision.v2 — E07

Decision ID, candidate and cluster, arm/allocation manifest, policy ID/version/digest, disposition TAKE|WAIT|SKIP, named clause results, opportunity arbitration set/winner, economic-assumption references, reason, validity, clocks and producer epoch. It does not size money.

risk_decision.v2 — E08

Risk decision ID, decision/candidate, account/risk cell/environment, disposition ALLOW|DENY|REDUCE_ONLY, named clause evaluations, authoritative exposure snapshot, policy digest, maximum quantity/notional/leverage, loss/correlation budgets, protection requirements, reservation ID/expiry, price/volatility assumptions, validity and denial reason. Default uncertainty denies increasing exposure but preserves reductions.

risk_reservation.v1

Reservation ID, risk decision, account/cell/instrument, reserved amount and unit, state REQUESTED|HELD|COMMITTED|RELEASED|EXPIRED|REVOKED, expiry, owner, producer epoch and linked execution/campaign facts. Terminal release is exactly once.

execution_authorization.v2 — E08 to E09

Immutable candidate/decision/risk/reservation lineage; account/venue eligibility; exact direction, position effect, approved quantity/notional ceiling; entry/invalidation/target geometry; allowed liquidity/time-in-force/order roles; protection deadline/budget; validity; producer fencing token. E09 may choose mechanics only inside these bounds.

emergency_exit_authorization.v1

Verified position snapshot, maximum reducible quantity, side/position mode, urgency tier, worst acceptable price for Tier 1, whether Tier 2 market is permitted, named trigger/evidence, standing policy ID/signature, expiry, serial key and audit reason. Absolute exposure after execution must be ≤ before exposure.

execution_cmd.v2 — internal E09

Command/attempt/idempotency IDs; authorization/reservation; account/instrument/venue; order side/position side/effect; quantity/price ticks; order type/TIF/post-only/reduce-only/close-position/working type/price protect/STP; role; deadline/urgency; retry budget; adapter route; expected prior order state; producer epoch.

03.9Control-plane, evidence, and manifest contracts

producer_lease.v1

Lease ID, authoritative topic/scope, producer service/instance, unsigned monotonic fencing token, issued/not-before/expires/revoked times, activation manifest, issuer, state and signature. Consumers store the highest accepted token per scope and reject lower/expired/revoked tokens even when messages arrive later.

engine_attestation.v1

Runtime identity tuple: contract bundle version + manifest SHA, config bundle SHA, risk policy SHA/reference, build commit, artifact digest, parameter set/digest, instrument map, fee model, universe, activation manifest, producer epoch, environment, host identity and startup receipt.

contract_bundle.manifest.v1

Ordered artifact paths, media types, schema IDs/versions, SHA-256, ownership, compatibility class and canonical manifest hash. A version string alone never identifies a bundle; current 1.37.0 manifest drift demonstrates why.

activation_manifest.v1

Exact deployed artifacts, services, logical topic bindings, capsules, symbols, sides, timeframes, experiment arm/allocation, account/risk cell, permitted authority, lease scope, limits/policy refs, start/expiry, approvals and rollback manifest.

trial_registration.v1

Permanent trial/family ID; hypothesis; formula/parameters; data revisions/ranges; symbols/sides/timeframes/regimes; entry/exit/cost/fill models; sample unit; split/purge/embargo; primary metric; multiplicity family; power/sample rule; promotion/demotion thresholds; frozen timestamp; owner/signature; result access audit.

replay_receipt.v1

Input segment hashes/offsets, receipt/watermark fidelity class, build/config/contract/parameter/instrument digests, checkpoint identity, run seed if any, thread/platform, output segment hashes, state checksums, test suite result, divergence links and signer.

bus_map.v1Treat subjects as logical future binding.Initial authoritative adapter is current hash-chained file ledger; NATS separately certified.

Reader/writer rule

  1. Publish new schema and compatibility manifest.
  2. Add shadow/dual reader; validate examples and property tests.
  3. Dual-publish from one authoritative source event; compare normalized semantic content.
  4. Move non-authoritative consumers first, then reconciliation/evidence consumers.
  5. Move authority only when completeness and rollback gates pass.
  6. Stop old writes; retain old readers through audit window.
  7. Remove bridge only when no consumer or runbook depends on it.

Down-conversion may drop only fields explicitly marked non-material by the compatibility manifest. No converter may guess a required material field. Major-version unknowns reject; additive minor fields are preserved when supported.

03.12Schema, client, and contract release process

  • JSON Schema plus normative invariant tests, golden valid/invalid vectors, and generated client round trips for every supported language.
  • Property fuzzing: unknown enum, missing field, extreme integer, duplicate key, malformed UTF-8, hash mismatch, wrong producer, stale epoch, clock inversion and additive unknown fields.
  • Consumer-driven compatibility tests run against every deployed reader version listed in the compatibility manifest.
  • All schema/config files enter the byte-level manifest; CI fails on unmanifested bytes or same-version changes.
  • Examples validate in CI but never define compatibility.
  • Release receipt records schema diff, semantic classification, owners, migration, consumers, test hashes and rollback.
Definition of done. A contract exists only when authoritative producer and consumer implementations validate it, compatibility is proven, metrics/quarantine exist, and a replayed event traces through its full lineage. A schema file alone is not an implementation.
